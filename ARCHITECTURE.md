# Skycoach Reels Ad Analyzer — Архитектура сервиса

## 1. Контекст и бизнес-задача

Сервис автоматизирует анализ рекламных интеграций маркетплейса игровых услуг **Skycoach** в Instagram Reels.
Инструмент предназначен для инфлюенс-менеджеров и решает три ключевые задачи:
1. **Сбор объективных метрик ролика:** просмотры, лайки, комментарии, дата публикации, автор (с корректной обработкой недоступных значений).
2. **Классификация интеграции:**
   - **0:** Про Skycoach ничего нет.
   - **1:** Упоминание (логотип в кадре, название голосом или текстом), но продукт не рекламируется.
   - **2:** Прямая реклама продукта Skycoach (описание услуги, бустинг, валюта, призыв к действию, промокод).
3. **Оценка заметности и качества интеграции (1–5):** с обоснованием (хронометраж показа, % площади кадра, голосовой/текстовый призыв) и детектированием дефектов размещения баннера (баннер обрезан, слишком мелкий, перекрыт интерфейсом).

## 3. Компоненты системы

### 3.1. Web API & UI (FastAPI)
- **`POST /api/tasks`**: принимает массив URL (до 20 штук).
  - Нормализует ссылки (убирает query-параметры `?utm_...`, приводит к каноническому виду).
  - Проверяет наличие в базе данных (кэш): если ссылка уже успешно анализировалась ранее, результат возвращается сразу без повторного запуска воркера.
  - Новые ссылки ставятся в очередь, API мгновенно возвращает список `task_id` со статусом `PENDING`.
- **`GET /api/tasks`**: возвращает список всех задач с пагинацией, текущими статусами (`PENDING`, `PROCESSING`, `COMPLETED`, `FAILED`) и готовыми метриками.
- **`GET /api/tasks/{task_id}`**: детальный статус и результат конкретной задачи.
- **Frontend**: легковесный интерфейс (Jinja2 + Tailwind/DaisyUI + автообновление таблицы статусов раз в 2–3 секунды). Поле для ввода ссылок (построчно), статус-индикаторы, таблица с бейджами классов и подробным обоснованием.

### 3.2. Фоновая очередь (Redis + RQ / Celery)
- Обеспечивает асинхронную обработку без блокировки веб-сервера.
- Изолированный пул воркеров с настраиваемым параллелизмом.
- Наличие жестких таймаутов на задачу (например, `timeout=180s`), предотвращающих зависание на длинных видеопостах.

### 3.3. Модуль извлечения данных (Instagram Extractor)
- На базе `yt-dlp` с оптимизированными флагами (`-f "b[height<=720]"`, `--no-check-certificate`).
- Извлекает метаданные:
  - Количество просмотров (`view_count`);
  - Лайки (`like_count`);
  - Количество комментариев (`comment_count`);
  - Автор (`uploader` / `channel`);
  - Дата публикации (`upload_date`).
- **Строгое правило:** если метрика скрыта/недоступна в соцсети — сохраняется `null` / `"N/A"`, а не `0`.
- В случае приватного, удаленного или заблокированного ролика генерирует строго типизированное исключение с человекочитаемым объяснением для менеджера.

### 3.4. AI-движок анализа видео и интеграций
- **Основная модель:** **`Qwen3.8-Omni-Flash`** (через OpenRouter / DashScope API).
- **Почему выбрана:**
  - Нативная мультимодальность: воспринимает визуальный ряд и аудиодорожку одновременно в одном запросе.
  - Точный OCR мелких деталей (детекция узких баннеров, промокодов, игрового контекста: Valorant, PoE, WoW).
  - Рекордно низкая стоимость (~$0.15 за 1M входных токенов — в 8–10 раз дешевле аналогов).
- **Схема структурированного ответа (Structured Output):**
  ```json
  {
    "has_skycoach": true,
    "integration_class": 2,
    "prominence_score": 4,
    "banner_duration_seconds": 10.5,
    "screen_percentage": 14.5,

    "has_text_cta": true,
    "promo_code": "VALFUN",
    "defects": [],
    "deduction_recommendation": "No deduction (Full payout)",
    "reasoning": "Баннер Skycoach расположен сверху по центру, четко виден на протяжении всего ролика (10.5 сек), занимает ~14% кадра. Содержит рекламу бустинга и промокод VALFUN. Дефектов размещения не обнаружено."
  }
  ```

## 4. Сравнение пайплайнов анализа (Альтернативные ветки)

Если качество end-to-end VLM на специфических роликах окажется нестабильным, архитектура предусматривает переключение на альтернативные пайплайны обработки:

| Pipeline | Плюс | Минус |
|---|---|---|
| **Video → VLM → yes/no** | Самый простой, сохраняет визуальный контекст | Может быть дорогим |
| **Video → VLM → structured features → Jev** | Jev хорошо подходит для стабильного decision layer | Теряешь часть исходной информации |
| **Frames + ASR + OCR → Jev** | Очень дёшево и быстро | Нужно хорошо собрать признаки |

*Примечание к Jev (Decision Layer):* выделение признаков через VLM с последующей передачей в детерминированный слой правил (Jev / Rule Engine) позволяет жестко фиксировать бизнес-логику (например: если площадь баннера меньше порога — назначать удержание за мелкий баннер, если координаты баннера выходят за край кадра — удержание за обрезку).

## 5. Обработка краевых случаев (Edge Cases)

В соответствии с требованиями приёмки:
1. **Приватный / закрытый аккаунт:** `yt-dlp` возвращает ошибку доступа $\to$ задача завершается статусом `FAILED` с текстом: *«Аккаунт приватный или доступ ограничен»*.
2. **Удаленный ролик:** возвращается статус `FAILED` с текстом: *«Ролик не найден или был удален»*.
3. **Ролик без звука:** модель корректно обрабатывает видеоряд, фиксирует отсутствие звуковой дорожки (`has_voice_cta: false`), не падает с ошибкой.
4. **Длинный ролик (> 90–180 сек):** скачивается в сжатом разрешении (480p/720p), лимит таймаута воркера защищает очередь от зависания.
5. **Повторная ссылка:** срабатывает уровень кэширования в БД (проверка по нормализованному URL) $\to$ мгновенный возврат сохраненных данных без запуска задач.
6. **Невалидная ссылка:** валидация на этапе FastAPI схемы $\to$ немедленный ответ с ошибкой формата URL без нагрузки на воркеры.

## 6. План развертывания (Deployment)

1. **Контейнеризация:** `Dockerfile` (мультистейдж Python 3.13 + ffmpeg) + `docker-compose.yml` (сервер, воркер, redis).
2. **Публичный хостинг:** **Railway** или **Render**:
   - `web`: FastAPI сервис с публичным HTTPS URL.
   - `worker`: фоновый воркер RQ.
   - `redis`: легковесный инстанс для очередей задач.
   - База данных: SQLite (монтируемый volume) или PostgreSQL.
