# Skycoach Reels Ad Analyzer

> **Сервис автоматического анализа рекламных интеграций маркетплейса игровых услуг Skycoach в Instagram Reels.**

Инструмент разработан для инфлюенс-менеджеров Skycoach. Сервис принимает до 20 ссылок на Instagram Reels / YouTube Shorts за один запрос, асинхронно обрабатывает их в фоне и предоставляет структурированный отчет: объективные метрики, класс интеграции (0, 1, 2), оценку заметности (1–5 ⭐), детекцию дефектов баннера и точный расчет удержаний по регламенту выплат.

## 🚀 Архитектурная схема

```mermaid
flowchart TD
    User([Инфлюенс-менеджер]) -->|Ввод до 20 ссылок| UI[Веб-интерфейс Tailwind + Polling]
    UI -->|POST /api/tasks| API[FastAPI Web Server]
    
    subgraph CoreBackend [Серверная часть]
        API -->|1. Проверка URL в кэше| DB[(База данных SQLite WAL / PostgreSQL)]
        API -->|2. Постановка новых URL в очередь| Redis[(Redis Queue: skycoach_reels)]
        API -->|3. Мгновенный возврат task_id| UI
        UI -.->|Live polling раз в 2 сек| API
    end

    subgraph WorkerPool [Фоновый воркер RQ]
        Redis -->|Забор задачи| Worker[Background Worker]
        Worker -->|1. Загрузка потока и метрик| Extractor[yt-dlp Extractor]
        
        alt Приватный / удаленный ролик
            Extractor -->|Typed Exception| Worker
            Worker -->|Запись статуса FAILED + текст ошибки| DB
        else Успешное скачивание (<=720p)
            Extractor -->|Метрики + temp MP4| Worker
            Worker -->|2. Восприятие видеоряда и звука| VLM[Multimodal AI: Gemini 2.5 / Qwen-Omni]
            VLM -->|Structured JSON признаки| Worker
            Worker -->|3. Расчет удержаний и вердикта| Rules[Deterministic Skycoach Rule Engine]
            Rules -->|4. Запись статуса COMPLETED| DB
            Worker -->|5. Удаление временного MP4| Cleanup[Auto Cleanup]
        end
    end
```

## 1. Как запустить локально

### Вариант А: Через Docker Compose (Рекомендуемый, все сервисы в 1 команду)

1. Клонируйте репозиторий:
   ```bash
   git clone <URL_РЕПОЗИТОРИЯ>
   cd Skycoach
   ```
2. Скопируйте шаблон переменных окружения:
   ```bash
   cp .env.example .env
   # При необходимости укажите GEMINI_API_KEY или OPENROUTER_API_KEY
   # (Если ключи не указаны, сервис работает в безопасном эвристическом режиме)
   ```
3. Запустите стек контейнеров:
   ```bash
   docker-compose up --build
   ```
4. Откройте интерфейс в браузере: **`http://localhost:8080`**  
   Интерактивная документация API (Swagger): **`http://localhost:8080/docs`**

---

### Вариант Б: Локальный запуск через `uv` (Быстрая разработка)

**Предварительные требования:** Python 3.11+, `uv`, `ffmpeg`, локальный Redis.

1. Установите зависимости проекта:
   ```bash
   uv sync --extra dev
   ```
2. Убедитесь, что Redis запущен на `localhost:6379`:
   ```bash
   redis-server
   ```
3. В первом терминале запустите веб-сервер FastAPI:
   ```bash
   uv run uvicorn src.main:app --reload --port 8080
   ```
4. Во втором терминале запустите фоновый воркер:
   ```bash
   uv run rq worker skycoach_reels
   ```

## 2. Использованные внешние сервисы и обоснование выбора

| Компонент / Сервис | Что делает в системе | Почему выбран (Обоснование) |
|---|---|---|
| **yt-dlp** | Извлечение объективных метрик (`views`, `likes`, `comments`, `author`, `upload_date`) и скачивание сжатого видеопотока ($\le 720p$). | Бесплатный инструмент с открытым исходным кодом, максимальная гибкость селекторов качества и прямое извлечение медиапотоков Instagram/Shorts/TikTok без обязательной платной подписки. |
| **Google Gemini 2.5 Flash** *(или Qwen 2.5 Omni)* | Мультимодальный анализ видеоряда и аудиодорожки в едином контексте. | **Рекордно низкая стоимость:** $\approx \$0.001$ за ролик (в 8–10 раз дешевле GPT-4o). Нативная поддержка видео со звуком, превосходный OCR мелких игровых баннеров и нативная поддержка Pydantic Structured Outputs. |
| **Redis + RQ (Redis Queue)** | Асинхронная очередь и управление пулом фоновых воркеров. | Минималистичный и надежный инструмент для Python без избыточного оверхеда Celery. Нативная поддержка жестких таймаутов (`timeout=180s`) для защиты от зависаний. |
| **SQLite (WAL mode)** / **PostgreSQL** | Персистентность задач, метрик и кэширование. | В режиме WAL (Write-Ahead Logging) SQLite выдерживает высокую параллельную нагрузку без блокировок чтения. Поддерживается переключение на PostgreSQL одной переменной `DATABASE_URL`. |
| **Детерминированный Rule Engine** | Расчет процентов удержания (20%, 30%, 100%) и статуса выплаты. | **Принцип разделения ответственности:** Нейросеть отвечает только за объективное восприятие (секунды, % площади, наличие CTA), а математический расчет штрафов зафиксирован в коде, исключая галлюцинации LLM в финансовых вопросах. |

## 3. Регламент выплат и шкала штрафов (из `banner_review_examples.pdf`)

| Дефект размещения | Удержание | Пояснение и логика |
|---|:---:|---|
| **Дефектов нет** | **0%** | Полная выплата (Full payout). Баннер расположен корректно, виден на протяжении ролика, не перекрыт. |
| **Баннер обрезан по краю** (`cut_off_edge`) | **-20%** | Часть баннера или логотип срезаны левым, правым или верхним краем кадра. |
| **Перекрыт интерфейсом / камерой** (`overlapped_by_ui`) | **-20%** | Баннер расположен слишком низко (перекрыт плашкой описания автора или кнопками Reels), либо попал под вырез фронтальной камеры. |
| **Слишком мелкий баннер** (`too_small`) | **-30%** *(или -20%)* | Баннер занимает $< 4\%$ площади кадра, мелкий нечитаемый текст. |
| **Баннер не виден / полностью перекрыт** (`not_visible`) | **-100% (0)** | Исключение из оплаты (Excluded / No payout). Баннер отсутствует или полностью закрыт элементами геймплея. |

## 4. Проверка приёмочных критериев (Edge Cases)

Все сценарии приёмки покрыты автоматическими тестами в [`tests/test_acceptance.py`](file:///Users/andrejmelnejcuk/Career/Skycoach/tests/test_acceptance.py):

| Сценарий ТЗ | Поведение системы | Статус |
|---|---|:---:|
| **Приватный ролик** | Ошибка перехватывается экстрактором, задача переходит в статус `FAILED` с текстом: *«Аккаунт приватный или доступ ограничен»*. Сервис не падает. | ✅ Проверено |
| **Удалённый ролик (404)** | Перехватывается экстрактором, задача переходит в `FAILED` с текстом: *«Ролик не найден или был удален автором»*. | ✅ Проверено |
| **Ролик без звука** | Экстрактор выставляет `has_audio=False`, AI анализирует видеоряд, фиксирует `has_voice_cta=False`, задача успешно переходит в `COMPLETED`. | ✅ Проверено |
| **Длинный ролик (> 180с)** | Ограничение хронометража, задача переходит в `FAILED` с сообщением о превышении лимита длительности, очередь не блокируется. | ✅ Проверено |
| **Повторная ссылка (кэш)** | Нормализуется URL (удаляются UTM/igsh), находится существующая запись `COMPLETED`, результат отдается за 10 мс (`is_cached: true`). | ✅ Проверено |
| **Невалидная ссылка** | Валидатор мгновенно формирует запись `FAILED` с понятным текстом ошибки формата ссылки. | ✅ Проверено |
| **Скрытые счетчики (лайки/комментарии)** | Если автор скрыл лайки — сохраняется `null` (`None`), в интерфейсе отображается серый бейдж `N/A`, а **не число `0`**. | ✅ Проверено |
| **Пакет > 20 ссылок** | API немедленно возвращает HTTP 422 с пояснением лимита. | ✅ Проверено |

Запуск всех 35 тестов:
```bash
uv run pytest -v
```

## 5. Ограничения системы

1. **Anti-bot защиты Instagram:** При массовых параллельных запросах с одного IP хостинга Meta может временно блокировать запросы или требовать авторизацию.
2. **Лимит хронометража:** Установлено жесткое ограничение на 180 секунд на один ролик для защиты пула воркеров от перегрузки.
3. **Объем видео:** Видеопоток скачивается в оптимизированном разрешении ($\le 720p$), что ускоряет сетевую передачу, но может снизить точность распознавания микроскопического текста (менее 1% экрана).

## 6. Что бы мы сделали следующим шагом (Roadmap)

1. **Ротация прокси и Fallback-скрейпер:** Интеграция пула резидентных прокси и резервного API (например, RapidAPI Instagram Scraper) при возникновении CAPTCHA у yt-dlp.
2. **Локальная CV-модель (YOLOv11):** Обучение легковесной нейросети детекции логотипов на GPU для предварительной фильтрации кадров (сократит обращение к внешним VLM на 70%).
3. **Двусторонняя интеграция с Google Таблицами / CRM Skycoach:** Вебхуки для автоматического обновления статусов выплат блогерам в корпоративной таблице после проверки инфлюенс-менеджером.
4. **Индивидуальная подстройка зон интерфейса под модели смартфонов:** Автоматическое наложение масок интерфейса iPhone Dynamic Island / Android Punch-hole для пиксельно точной детекции перекрытия баннера.
